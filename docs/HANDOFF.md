## 1. 目标及范围演进

最初目标是建立薛立斋及后世思想承继医家的可审计谱系和医案知识体系。先产出了人物／关系／书目报告和工作簿，随后转向薛己自著全文。三书试点和每书十案已被用户明确否定为最终交付范围；目前应逐书完整组织全部现有文本。用户允许从网络寻找公开馆藏影像，不要求用户提供影像。用户要求维护一个有完整内容的权威医案 Markdown，并限定只处理本任务文件。

当前交接约定：接手 agent 依据目标、依赖及质量要求自主调度并持续执行，不继承旧聊天中的轮次、批次大小、工作时长或例行报告频率。下列默认顺序帮助定位下一项，允许合理调整；工具也可替换。包内校验器均为辅助工具，运行 `verify_handoff.py` 不作为开始工作的前置条件。

当前优先级是薛己直接著作。后世赵献可—高斗魁—吕留良路径及其他候选谱系暂后置，不要因旧底稿的“暂定正式”自动扩张主语料。范围最终可至当代，但当代材料须有权利与脱敏分级，未授权材料只记线索。未来工具面向临床专业人员研究历史医案，不向真实患者作个体化诊疗或处方。

## 4. 数据结构与编辑方式

主稿包含书级元资料、`source_id` 原文记录，以及独立 `case_id` 和 `text_unit_id` 区域。正文同时在来源区和案例区出现是有意的溯源设计，不是要删除的重复。结构化区先列案例再列非案例，阅读原始顺序应按来源 ID 与字符跨度重排。

- `case_id`：如 `XJ-NKZY-C-V2-P030-2`，来自第二卷第30来源段第二案。
- `text_unit_id`：通论、署名、集体转归、交叉参照、方论等；具体类别见 `unit_kind`。
- `source_ref`：固定来源记录。`source_start_char` 是 Python Unicode 字符的零基起点；`source_end_char_exclusive` 是排除的终点，不是字节索引或影像列号。
- 跨段同案可用 `continued_source_ref` 及其起止字段（限一段续文），或 `continued_source_refs`（复数，2026-09-29 新增，`work/audit_corpus.py` 已支持）：分号分隔的 `sid:start:end` 三元组链，支持任意长度多段拼接，两者互斥、不可同用一条记录。渲染文本必须依序为主段＋各续段原文，段间以空行（`\n\n`）相连，且每段字符跨度独立纳入该 `sid` 的覆盖校验（可与另一结构化记录在同一 `sid` 内以不重叠字符区间分摊，用于处理单一物理行内含多名患者的情形）。为 `XJ-BYCY`（保婴粹要，四库全书无标点逐行来源，单案常跨 2–10+ 行，另见至少一处单行六人以「○」分隔的集体转归案例）新增，起草前已用合成数据验证通过多段链式与同行不重叠分摊两种场景；尚无任何正式记录使用此字段。
- **`validate_structured_units` 的两处配套修正（2026-09-29，为支持 XJ-BYCY 起草时发现）**：(1) 原本用无参数 `.strip()` 从渲染正文中提取 `actual`，会一并剥掉 U+3000（全形空格），但 `expected`（原始切片）不剥；`XJ-BYCY` 章节标题／`治驗` 小标行本身以「　　　」起首，会因此被误判为"原文与所引跨度不符"。已改为只剥 ASCII 空白（` \t\n\r\x0b\x0c`），保留 U+3000。(2) `coverage_id` 覆盖校验原本用固定 `{n:03d}` 三位补零拼回 `source_id`，`XJ-BYCY` 四位补零（`L0001`…`L1139`）在编号小于 1000 时会拼错（如 574 拼成 `L574` 而非 `L0574`）导致找不到记录；已改为从 `index` 中任一同前缀既有 `source_id` 动态推断补零宽度。两处修正后已用全量 5357 条记录重新验证 0 回归、`text_sha256` 不变，另有合成数据单测覆盖。
- 以 `_quote` 结尾的字段必须是该案全文的连续原句。拼接多处引文不得冒充连续原句，应使用多个片段及定位。
- 诊断、病机、治疗、转归都记录原书叙述，不推现代病名、实际疗效或统计因果；相同医案重见保留各自原文并建立关系。
- `shared_management_ref`、`shared_case_refs` 标识多人共用叙述；`possible_repeat_source_ref` 是候选重出关系，未等于确认同人。
- `baseline_id`／`comparison_id`（2026-09-30 新增，主稿末尾 `BASELINE_COMPARISON_BEGIN/END` 区）：思想基线候选卡（`p{k}_*` 支持段、`c{k}_*` 反例／限度，`p{k}_quote` 逐字等于 `source_ref` 跨度）与比较记录（`comparison_category` 仅五类，`a_*`／`b_*` 双方定位）。全为模型起草、未人工复核（`review_status: model_drafted_not_human_reviewed`）；不作师承或影响认定。校验在 `validate_baselines_and_comparisons`。 第二批起支持跨物理行引文：`p{k}_continued_source_refs`（`sid:start:end` 链），续行文字与首段直接连接、不加分隔符后须逐字等于 `_quote`（仅保嬰粹要使用）；“至少两段来源”按各段起始记录计。累计 46 卡、83 条比较。
- `possible_repeat_case_refs`（2026-09-30 新增，校验器检查引用可解析）：机械筛出的候选重复案例（字形归一 n-gram 重合），配 `possible_repeat_metrics`（相似度、强弱）、`possible_repeat_status: candidate_not_confirmed_same_patient`。71 对、127 案；覆盖八书跨书重述（如女科撮要↔立斋外科发挥、外科枢要↔疠疡机要）及癘瘍機要书内重出。仅为候选，不得据此合并案例或认定同一患者；相同案的措辞、方名、剂量差异可用于版本比较。
- 影像状态和研究检索状态独立：`not_started`、`sampled_verified`、`sampled_variants_found` 是现存源记录影像枚举；即便 `sampled_verified` 也只代表历史抽查标记。
- `needs_review` 默认排除；`source_research_with_caveats` 只表示可带来源限制研究。所有材料尚未统一完成面向外部问答的资格审定。

为了稳定接续，先只增元资料、证据、结构化单元和报告；来源正文必要校订应保留原读、图读、采用读法、版本／页码、理由和复核方式，并同步迁移所有受影响字符跨度。不能只改案例区或只改来源区。

## 5. 已确定的后续执行方法

第一项是《女科撮要》全量来源对账：其序 2 段、卷上 257 段、卷下 334 段。从现有元资料的中医笈成页面确认版本／权利，在允许条件下逐书取得完整电子来源；记录取得日期与文件散列。比较实际目录、卷次、段次和每段文字，保留现行历史校改与新来源差异，不运行旧整书重建器覆盖现有元资料。没有网页访问能力时，先对包内全文做边界整理并明确外部对账待核，继续可做事项。

之后逐完整篇章切分：每个可辨识患者叙事保留闭合全文，合并跨段续案，分拆段中多人，保留集体处置、来书署名及原刻注。全部非病例文字也纳入覆盖。逐篇自动验原文与引用，然后对病例、理论、附方、小字分层选取公开影像抽检。既要有已知疑点的风险样本，也要有预先固定的普通样本；记录抽样依据，不以样本推全书正确率。

- **插入新结构化区块的位置陷阱**：`audit_corpus.py` 的 `RECORD_RE` 用 `(?=\n#{3,5} |\Z)`（3～5 个 `#`）判定原始来源段落正文的终止边界，而本项目结构化区块的说明性标题惯用 `## 书名「章节」...`（仅 2 个 `#`），不满足该终止符。若把某书的首次结构化插入直接安插在该书自身原始段落之后、紧邻下一本书的 `# 《书名》` 标题之前，`## ` 标题不会被识别为边界，导致前一条原始段落的正文被机械地一路吞并到插入内容里第一个 `### ` 标记为止，进而使 `text_sha256`（来源文本层摘要）悄然漂移，而 `validate_structured_units` 未必报错（因为该原始段落本身未被任何结构化记录引用）。**规避方法**：任何新书的首次结构化插入，一律追加在当前文档中最新一个已有结构化区块的末尾（即最近一次插入的 `<!-- ..._END -->` 标记之后），不要紧邻任何原始来源段落或下一本书标题插入；插入后必须核对 `work/audit_corpus.py` 输出的 `text_sha256` 与插入前一致，若不一致须立即定位并搬回正确位置（2026-09-29 曾在《口齒類要》繭唇一／口瘡二／齒痛三首次插入时踩中并修正此坑）。

- **书间 Markdown 分隔线被吞入末段正文的已知瑕疵（不要主动"修复"）**：`RECORD_RE` 只在 3～5 个 `#` 处终止，而部分书与书之间历史上用了 `\n\n---\n\n` 分隔线才接下一本书的 `# 《书名》` 标题（单个 `#`，不满足终止符）。目前已知受影响的仅 3 处（`books()` 解析后每书最后一条记录的 body 尾部若含 `\n\n---` 即为受影响）：`XJ-NKZY-V2-P368`、`XJ-WKSY-V4-P417`、`XJ-LYJY-V3-P221`；其余 5 处书边界原文没有 `---` 分隔线，不受影响。**既定处置先例（2026-09-29 确认三处一致）**：不删除／不改动原始来源层的 `---`（改动会牵动 `text_sha256`，且早于本轮已有两处这样处理），而是让覆盖该段落的结构化单元（`XJ-NKZY-U-V2-P368-1`、`XJ-WKSY-U-V4-P417`、`XJ-LYJY-U-V3-P221`）的 `source_end_char_exclusive` 直接涵盖含 `---` 在内的完整字元数，并附 `editorial_separator_note` 字段说明。之后若在其他书目末段结构化时遇到同样尾随 `---` 的情况，比照此三例处理，不要单独改动原始正文去"清理"它。
