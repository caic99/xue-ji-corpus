# 提交前自审与证据审核要求

每次研究变更应先完成自审与必要修订，再创建 PR。适用范围包括数据、程序、文档、提交信息和 PR 描述。外部审核服务是否执行必须有实际记录；合并本身不能作为审核已完成的证据。

1. 记录当前上游基线、变更范围及未覆盖范围。从 fork 的独立分支开发。
2. 重新阅读本轮改动涉及的完整案文窗口，检查语义、相对时序、说话者、跨来源边界、否定与未载状态。逐字证据正确不代表解释正确。
3. 完成第二遍差异审查，列出发现、修订与保留理由。模型自审明确标为模型自审，不能称独立专家审校。
4. 执行 `python3 research/run_research_checks.py --report-date YYYY-MM-DD`，保留真实结果。对发现的错误增加有针对性的回归检查；远端 CI 的状态单独报告。
5. 审查新增及修改文件、提交信息、PR 标题与正文，限于可公开的研究内容及必要维护信息。运行 `research/check_publication.py` 前将预期发布文件纳入 Git 索引；此检查只覆盖受跟踪文件，不能替代人工审查。
6. 未解决的本次变更错误不得带入 PR；研究本身尚未裁定的异文、语义与影像问题须逐项保留不确定性、来源和排除规则。不能把未核事项标为通过。
7. 在自审记录中列出已完成的检查、剩余风险及适合审核的范围，再创建 PR。发布后核对远端差异与本地预期一致，检查是否实际运行 CI。

每个 PR 应链接一份有日期的自审记录。既有报告保留其当时数据，后续增量用新的报告说明；不得为消除差异而覆盖历史结论。古籍正文、固定样本与原典见证发生变化时，须另行说明迁移及定位影响。
